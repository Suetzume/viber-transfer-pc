## 1. Обзор релиза v2.0.0

Версия `v2.0.0` представляет собой **финальный масштабный релиз настольного приложения (Desktop PC Edition)** для кроссплатформенного переноса данных Viber между Android и iOS (iPhone). 

В данном релизе полностью завершена интеграция физического и логического слоя устройств (Слой 6: Аппаратные коннекторы и сканеры устройств), решена задача реального распознавания подключенных телефонов и локальных баз данных, а также подготовлен фундамент для Phase 2 (мобильные компаньоны).

## 2. Ключевые компоненты и архитектурные реализации

### 2.1. Android Device Connector (`src/devices/android/adb-connector.js`)
* **Автоматический поиск исполняемого файла ADB:**
  - Сканирование системного `PATH` (`where adb` / `which adb`).
  - Проверка переменных окружения `ANDROID_HOME` и `ANDROID_SDK_ROOT` (`platform-tools/adb.exe`).
  - Проверка стандартных каталогов установки Android Studio (`%LOCALAPPDATA%\Android\Sdk\platform-tools`).
* **Интеллектуальный парсер вывода `adb devices -l` (`parseAdbDevicesOutput`):**
  - Определение статуса авторизации (`device` vs `unauthorized` vs `offline`).
  - Извлечение имени модели устройства (напр. `Pixel 7`, `Galaxy S22`), аппаратного идентификатора и `transport_id`.
  - Игнорирование сервисных логов запуска демона ADB (`* daemon not running...`).
* **Трехуровневая стратегия обнаружения данных (3-Tier Extraction Strategy):**
  - **Tier 1 (Рекомендованный):** Прямое автоматическое обнаружение нешифрованных локальных баз Viber Desktop (`%APPDATA%\ViberPC\<номер>\viber.db`). Обеспечивает мгновенное чтение без необходимости рутования телефона.
  - **Tier 2:** Обнаружение официальных архивов резервных копий Google Drive (`viber_backup.zip`) в каталогах пользователя (Загрузки, Документы, Рабочий стол).
  - **Tier 3:** Прямое сканирование шины USB через ADB с проверкой наличия пакета `com.viber.voip` и версии Android.

### 2.2. iOS MobileSync & Backup Connector (`src/devices/ios/ios-connector.js`)
* **Обнаружение каталогов резервных копий Apple на Windows (`getMobileSyncBackupRoots`):**
  - Классический установщик iTunes: `%APPDATA%\Apple Computer\MobileSync\Backup\`.
  - Microsoft Store / Apple Devices App (UWP): `%USERPROFILE%\Apple\MobileSync\Backup\`.
* **Инспекция структуры бэкапа и `Manifest.db` (`inspectIOSBackup`):**
  - Определение реального имени устройства (напр. `iPhone 15 Pro Max`) и версии iOS из `Info.plist` / `Manifest.plist`.
  - Проверка наличия шифрования бэкапа (`IsEncrypted`).
  - Запрос таблицы `Files` для подтверждения присутствия контейнера Viber (`AppDomainGroup-group.viber`).
* **Предварительная валидация перед восстановлением (`validateBackupForRestore`):**
  - Контроль свободного дискового пространства с использованием встроенного `fs.statfsSync` ($\ge 1.5 \times \text{размер бэкапа}$).
  - Проверка отсутствия шифрования (пароля бэкапа iTunes).
  - Обязательное предупреждение о необходимости временного отключения функции «Локатор» (Find My iPhone) на целевом смартфоне (FMEA Риск 2).
* **Проверка системных драйверов Apple (`detectAppleServices`):**
  - Проверка наличия `AppleMobileDeviceService.exe` и `iTunes.exe`.

### 2.3. Единый фасад устройств (`src/devices/index.js`)
* Функция `scanAllDevicesAndBackups()` формирует целостную моментальную картину всей экосистемы (подключенные Android-смартфоны, аккаунты Viber Desktop, копии iPhone, системные службы).

### 2.4. Интеграция с BridgeServer и динамическим интерфейсом
* В `src/server/bridge-server.js` добавлены эндпоинты:
  - `GET /api/devices`: возвращает полный статус подключенного оборудования.
  - `POST /api/validate-backup`: выполняет аудит бэкапа iOS перед операцией.
* В графическом интерфейсе (`src/renderer/index.html`):
  - Добавлена кнопка **«🔄 Сканировать устройства»**.
  - Статусы устройств больше не являются статичной заглушкой: если физический телефон не подключен по USB и нет локального бэкапа, интерфейс честно отображает серый индикатор `USB не подключен` с инструкцией.
  - При наличии Viber Desktop или подключенного телефона через ADB выпадающий список автоматически заполняется реальными данными.

## 3. Матрица верификации тестами (TDD Matrix)

Все 12 тест-сьютов (44 теста) пройдены со 100% результатом:
1. `tests/foundation.test.js` (12 тестов):
   - TimeEngine: конвертация Unix Epoch $\leftrightarrow$ Apple Cocoa Epoch (смещение `978,307,200` с).
   - HashService: SHA-1 хеширование путей Manifest.db, разбиение на 2-символьные подкаталоги, SHA-256 CAS, MD5 отпечатки.
2. `tests/android-adapter.test.js` (4 теста):
   - Маппинг типов `extra_mime` $\leftrightarrow$ UIM MessageType.
   - Импорт из Android SQLite в UIM.
   - 100% Round-Trip Fidelity без искажения данных.
3. `tests/ios-adapter.test.js` (4 теста):
   - Маппинг CoreData `ZMESSAGETYPE` $\leftrightarrow$ UIM.
   - Dynamic KeyRebalancer: сканирование `MAX(Z_PK)` и сдвиг первичных ключей.
   - 100% Round-Trip Fidelity.
4. `tests/manifest-builder.test.js` (5 тестов):
   - Генерация бинарного plist `bplist00`.
   - Регистрация записей в `Manifest.db`.
   - PKZIP 2.0 архиватор/декомпрессор с CRC32 контролем.
5. `tests/migration-engine.test.js` (4 теста):
   - Сквозная миграция Android -> iOS с регистрацией в Manifest.
   - Сквозная миграция iOS -> Android с упаковкой zip.
   - Полный сквозной цикл Zero Data Loss: Android -> iOS -> Android.
6. `tests/bridge-server.test.js` (5 тестов):
   - Старт сервера и `/api/preflight`.
   - Обнаружение десктопных баз `/api/detect-desktop`.
   - Обнаружение физических устройств `/api/devices`.
   - Выполнение миграции по API `/api/migrate`.
   - Отдача статического интерфейса `index.html`.
7. `tests/devices.test.js` (10 тестов):
   - Парсер `adb devices -l` для различных состояний (`device`, `unauthorized`, `offline`, логи демона).
   - Парсер `Info.plist` (XML и бинарный формат).
   - Инспекция бэкапа и проверка Manifest.db.
   - Валидация перед восстановлением (шифрование, Find My iPhone).
   - Определение служб Apple.
   - Единый системный сканер `scanAllDevicesAndBackups`.

**Итог: 44 теста, 12 сьютов, 0 ошибок, время выполнения ~800 мс.**
