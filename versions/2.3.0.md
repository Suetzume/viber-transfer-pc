## Реализованные улучшения (Этап 2: Интерактивный мастер и честная миграция)

### 1. Полноценный 3-шаговый мастер в интерфейсе (Single Screen Wizard)
* **Шаг 1: Источник данных (Android):**
  - **Вкладка 1 (USB Смартфон):** отображает в реальном времени статус подключенного смартфона Xiaomi 13 Ultra (`2304FPN6DG`), версию Android 16, статус отладки и наличие Viber. Содержит техническое разъяснение ограничений No-Root Android 11–16 и кнопки быстрого перехода к официальным каналам извлечения.
  - **Вкладка 2 (Viber Desktop):** автоматическое обнаружение базы данных аккаунта в `%APPDATA%\ViberPC\<номер>\viber.db` + кнопка «📁 Выбрать файл...».
  - **Вкладка 3 (Google Drive Zip):** выбор официального архива `viber_backup.zip` через нативный диалог Windows.
  - **Вкладка 4 (Тестовый макет):** синтетический демо-режим изолирован в отдельную прозрачную вкладку с предупреждающим оранжевым бейджем.
* **Шаг 2: Приемник данных (Apple iPhone / MobileSync):**
  - Определение статуса служб Apple (iTunes / «Устройства Apple») с прямой ссылкой на загрузку из Microsoft Store.
  - Пошаговая инструкция из 4 действий по созданию незашифрованного бэкапа.
  - Автоматическое обнаружение каталога резервной копии в `%APPDATA%\Apple Computer\MobileSync\Backup\<UDID>` + кнопка ручного выбора папки.
* **Шаг 3: Сводка и валидация перед запуском:**
  - Информационная карточка с выбранным источником, приемником и режимом миграции.
  - Кнопка «Начать перенос» блокируется до тех пор, пока пользователь не укажет реальный источник или не переключится на демонстрационную вкладку.

### 2. Полное исключение скрытого/принудительного демо-режима
* Устранен хардкод `{ direction, demo: true }` в клиентском коде `index.html`.
* Флаг `demo: true` передается **исключительно** при явном выборе вкладки «Тестовый макет».
* Эндпоинт `/api/migrate` строго проверяет наличие и валидность путей (`sourcePath`, `targetPath`). Если источник не указан или файл отсутствует на диске — возвращается ошибка HTTP 400 с понятным объяснением.

### 3. Интеграция с нативной файловой системой Windows
* Добавлен API-эндпоинт `/api/browse`, запускающий нативные диалоги Windows (`OpenFileDialog` для файлов `.db`/`.zip` и `FolderBrowserDialog` для папок бэкапа iTunes) через PowerShell STA.
* Реализована автоматическая распаковка zip-архивов Google Drive через модуль `unpackZip` с извлечением `viber_messages.db` во временную изолированную директорию.
* Реализована прямая инъекция в бэкап iTunes: вычисление хеша `AppDomainGroup-group.viber/database/Chat.data` (`computeManifestFileId`), создание двузначной подпапки, запись SQLite базы и регистрация файла в `Manifest.db` с точным размером.

### 4. Комплексное дотошное тестирование (E2E Validation)
* Добавлен новый тест-сьют `tests/wizard-stage2.test.js` (7 тестов):
  1. UI Contract: верификация структуры 3 шагов, нативных кнопок выбора и отсутствия принудительного демо-флага.
  2. `/api/browse`: валидация API-контракта нативного диалога.
  3. `/api/migrate`: отказ с кодом 400 при отсутствии источника.
  4. `/api/migrate`: отказ с кодом 400 при несуществующем пути к файлу базы.
  5. `/api/migrate`: успешная миграция реального SQLite файла на диске (2 чата, 4 сообщения, Zero Data Loss).
  6. `/api/migrate`: распаковка и миграция официального архива Google Drive `viber_backup.zip`.
  7. `/api/migrate`: сквозное внедрение в реальный бэкап iTunes с созданием хешированного файла и обновлением `Manifest.db`.
