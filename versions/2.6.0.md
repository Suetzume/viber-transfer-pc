## Реализованные улучшения (Этап 5: Защита от ошибок Apple и мастер восстановления)

### 1. Предотвращение ошибок iTunes / Apple Devices (Ошибки 14 и 54)
* **Проблема FMEA:** Если пользователь создал резервную копию iPhone в iTunes с включенным флажком *«Зашифровать локальную копию»*, файл `Manifest.plist` содержит `<key>IsEncrypted</key><true/>`. При попытке прямой модификации базы данных или `Manifest.db` iTunes сверяет криптографические контрольные суммы (HMAC/AES) и на этапе восстановления выдает фатальный отказ (Error 14 / Error 54), блокируя перенос.
* **Решение в BridgeServer (`/api/migrate`):**
  - Перед началом внедрения данных в целевую копию iPhone сервер проводит аудит заголовков `Manifest.plist` и `Info.plist`.
  - При обнаружении флага `IsEncrypted: true` миграция превентивно блокируется с понятным кодом ошибки 400 и инструкцией:
    `«Резервная копия зашифрована паролем iTunes! Восстановление зашифрованного бэкапа после модификации будет заблокировано iTunes (Ошибка 14/54). Пожалуйста, снимите галочку «Шифровать локальную копию» в iTunes перед миграцией.»`

### 2. Live-диагностика целевого бэкапа (`/api/inspect-target`)
* Добавлен специализированный эндпоинт `/api/inspect-target` (и расширен `/api/validate-backup`), принимающий `targetPath`.
* В веб-интерфейсе при вводе или выборе пути к папке бэкапа на Шаге 2 запускается фоновая проверка:
  - Если бэкап зашифрован: мгновенно выводится предупреждающий янтарно-красный баннер.
  - Если бэкап открыт и содержит `Manifest.db`: выводится зеленый бейдж готовности: `«✓ Резервная копия готова к приему данных: Шифрование: Отключено (Безопасно). Наличие Manifest.db подтверждено.»`
  - Добавлена ручная кнопка `🛡️ Проверить бэкап на шифрование`.

### 3. Интеграция с проводником Windows (`/api/open-folder`)
* Добавлен системный эндпоинт `/api/open-folder`, который запускает процесс `explorer.exe` с передачей пути к каталогу бэкапа.
* На финальном экране миграции (`successCard`) размещена кнопка **«📂 Открыть папку бэкапа в Проводнике»**. Пользователь может в один клик увидеть измененный `Manifest.db` и внедренные подпапки с медиафайлами.

### 4. Интерактивный 4-шаговый мастер восстановления на iPhone
* Экран успешного завершения переработан в наглядную пошаговую памятку:
  1. **Отключите «Локатор»:** В настройках iPhone (*[Apple ID] ➔ Локатор ➔ Найти iPhone ➔ Выключить*).
  2. **Подключите iPhone к ПК:** Кабелем через USB и запустите iTunes или приложение «Устройства Apple».
  3. **Восстановите резервную копию:** Нажмите *«Восстановить из копии...»* и выберите обновленный бэкап.
  4. **Готово:** После перезагрузки телефона откройте Viber — все чаты, вложения и фото будут на месте. Включите «Локатор» обратно.

### 5. Автоматизированное тестирование и автономный бинарник

  - Детекция зашифрованного бэкапа (`IsEncrypted: true`).
  - Тестирование API `/api/inspect-target`.
  - Проверка блокировки `/api/migrate` при передаче зашифрованного бэкапа.
  - Тестирование API `/api/open-folder`.
* Обновлен бандлер `build-standalone.js` (внедрен модуль `media-pipeline.js`).
* Автономный `ViberTransfer.exe` пересобран (95.78 MB).
